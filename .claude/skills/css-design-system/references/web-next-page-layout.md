# web-next 画面更新ガイド

`/anatomy/bone-related-headache` で整えた画面構成を、他の教育ページへ適用する際に使う。
医療本文・見出し階層・表・図・出典を保持し、
依頼されたページの導入とレイアウトを更新する。以下の実装パスはリポジトリルートからの相対パス。

## 参照実装

| 用途 | 参照先 |
| --- | --- |
| 全体の外観、ヒーロー、余白、レスポンシブ | `web-next/app/anatomy/page.tsx` と `anatomy.css` |
| 教育ページへの適用例 | `web-next/app/anatomy/bone-related-headache/page.tsx` と `bone-related-headache.css` |
| 左目次、現在位置の表示 | `web-next/components/headaches/BoneRelatedHeadacheSidebar.tsx` |
| 本文保持・導線の契約 | `web-next/app/anatomy/bone-related-headache/page.test.tsx` |

CSSの数値・配色は現行実装を読んで選ぶ。このガイドにスタイル全文を複製しない。

## カテゴリー別の配色

レイアウトは共通化し、ヒーロー・開始ボタン・目次などの外観をカテゴリーの色で区別する。
分類は対象ルートに合わせる。たとえば骨の解説は `/anatomy/`、頸原性頭痛の疾患ガイドは
`/headaches/` の配色を使い、本文中の話題だけでカテゴリーを切り替えない。

| ルート | 色系統 | ヒーロー背景 | アクセント境界 | 選択中の目次背景 |
| --- | --- | --- | --- | --- |
| `/anatomy/**` | 青緑 | `#142733`（単色） | `#69b9a8` | `#193d46` |
| `/headaches/**` | インディゴ・ブルー | `#171d4b` → `#263b82` | `#9aaeff` | `#2e408f` |
| `/treatment/**` | プラム・紫 | `#321c3e` → `#623e70` | `#cfade0` | `#704580` |
| `/blocks/**` | アンバー・ブラウン | `#33251a` → `#67472b` | `#e2b86c` | `#805427` |

グラデーションの角度は参照実装では125度。細部の色（文字・ボタン・淡い背景・ホバー・フォーカス）は
下記の同一カテゴリーの現行CSSを参照する。表は導入・ナビゲーションのパレットであり、本文全体の色指定ではない。

| カテゴリー | 配色の参照実装（リポジトリルート相対） |
| --- | --- |
| アナトミー | `web-next/app/anatomy/bone-related-headache/bone-related-headache.css` |
| 頭痛疾患 | `web-next/app/headaches/migraine/migraine.css` |
| 治療 | `web-next/app/treatment/acute-treatment-of-headache/acute-treatment-of-headache.css` |
| 神経ブロック | `web-next/app/blocks/occipital-nerve-block/occipital-nerve-block.css` |

- 変更する配色の範囲は、ヒーロー背景・ラベル・トピック帯・開始ボタン、免責表示の淡い背景と文字、
  目次の背景・番号・現在位置・ホバー、フォーカス表示。背景だけ差し替えて文字色を取り残さない。
- 警告・危険・禁忌・エビデンスバッジの意味を持つ色、本文の図表やMermaidの配色は維持する。
  `--red`・`--orange` などの共通変数をカテゴリー色に一括置換しない。
- 同じカテゴリーの未対応ページへ展開する場合は既存パレットを使う。
  レガシーHTML用の「ページ別ヒーローカラー重複禁止」は、このカテゴリー統一には適用しない。
- 未定義のカテゴリーやユーザー指定色は、その依頼の範囲で選定する。
  色による区別に加え、ヒーローにも「頭痛疾患」「治療」「神経ブロック」などのカテゴリー名を表示する。

## 着手時の確認

- 対象はページのヒーロー、免責表示、本文、ページ内移動用の左目次。
  `/anatomy` は外観の参照に使い、3Dビューアの調整はこの手順に含めない。
- 対象TSX、ページCSS、目次コンポーネント、既存テストを読む。
  祖先の幅制限、Gridの伸長、モバイルでの上書きも確認し、見えている空白の原因を特定する。
- 対象ルートのカテゴリーと配色参照を選ぶ。「同じレイアウト」と「同じ色」を区別し、
  他カテゴリーのページを参照していても対象カテゴリーの色を適用する。
- `git diff` で先行変更を確認する。既存ページの外観更新だけなら、新規ルート登録や依存追加は行わない。

## ヒーロー

- `/anatomy` に揃える場合は、濃色の背景、左揃えのタイトル、控えめな英字ラベル、細いアクセント境界を使う。
- 実在する親ページへの導線と、本文中の実在する節への開始リンクを配置する。ページのタイトル・説明は保持する。
  カテゴリー一覧が未実装の場合はカテゴリー名の表示に留め、存在しないルートや無関係な転送先へリンクしない。
- 広い画面では主見出しと概要を2列に、狭い画面では1列にする。
  概要の件数や分類は対象ページの実データから求め、参照ページの数値をそのまま転記しない。
  件数が有益でなければ数値ブロックを増設しない。
- トピックはヒーロー末尾の境界線付きの帯にまとめ、長いラベルも折り返せるようにする。

## 免責表示

- コンパクト化にはネイティブの `details` / `summary` を使う。
  学術・教育・研究目的であることを閉じた状態でも示し、既存の免責全文は内部に保持する。
- 全幅の依頼では、外枠だけでなく本文の `max-width: 100ch` 等も解除する。
  左右に読みやすい余白を残し、使用可能な幅全体へ文章を流す。中途半端な位置で強制改行しない。
- モバイルでは要点ラベルの自然な折り返しを許容する。本文の文字サイズを過度に小さくして収めない。

## 左サイドバーと全幅本文

- ページ外枠を `width: 100%; max-width: none` とし、中央寄せ用の固定最大幅を解除する。
  左端に目次を置き、本文は目次を除く残りの画面幅へ伸ばす。本文を `100vw` にして横溢れさせない。
- Flexなら本文に `flex: 1; min-width: 0`、Gridなら本文列に `minmax(0, 1fr)` を使う。
  本文自身や祖先の `max-width` も確認する。横長の表は既存のスクロール枠内に収める。
- 目次の `sticky` 位置と節の `scroll-margin-top` には、共有ヘッダーと免責バナーの高さを含める。
  既存の `--ch-height` / `--ch-disclaimer-height` を参照し、目次の高さは可視領域に収める。
- 目次は淡い背景、区切り付きの見出し、実際の項目数、桁を揃えた番号で整理する。
  各行は押しやすい高さと余白を取り、現在位置は濃色、ホバーは淡色で区別する。
- ページごとのCSSリセットの有無を確認し、目次リンクにも `box-sizing: border-box` を適用する。
  `box-sizing` は継承されないため、サイドバー外枠だけの指定では不十分。
  行高に上下パディングが加算され、参照ページより縦長になっていないか確認する。
- `nav` に目的を表す `aria-label` を付け、現在項目だけに `aria-current="location"` を付ける。
  装飾番号は `aria-hidden` にし、既存のscroll-spy・アンカーID・キーボードフォーカスを保持する。
- 狭い画面では既存の目次非表示／開閉方式を尊重して1列へ切り替える。
  新しいモバイルメニューを依頼なく追加しない。

## 実装と検証

ページ専用CSSは既存のルートクラス配下に置く。共通トークン・`globals.css` の一括変更や、
`RelatedLinks`・用語ツールチップへのリセット波及を避ける。

リポジトリの `.claude/rules/tdd-mandatory-cycle.md` に従って契約を先に確認・更新する。
導線、免責全文、現在位置の意味付け、見出し・表・図の保持を検証し、CSS文字列の一致だけで表示確認を代用しない。

- 広いデスクトップ、900px付近、狭いモバイルで、本文幅・横溢れ・改行・目次の固定位置を確認する。
- 同一カテゴリーの配色が一致し、他カテゴリーと区別できること、通常・ホバー・選択中・フォーカスの
  各状態で文字が読めることを確認する。警告やエビデンス表示の色が変わっていないかも確認する。
- 免責事項の開閉、目次クリック、スクロール時の現在位置、キーボードフォーカスを確認する。
- `web-next/` で `bun run typecheck`、`bun run test`、`bun run lint`、`bun run build` を実行する。
  ユーザーがビルドを担当すると指定している場合、その指示が続く間は実行しない。
- ブラウザ表示を確認できなければ未確認と明示する。対象外のテスト失敗も結果に含め、全件成功と報告しない。
  過去セッションの失敗を恒久的な除外扱いにせず、今回の実行結果を確認する。

完了報告では変更した表示、検証結果、未実行の確認だけを簡潔に伝える。
