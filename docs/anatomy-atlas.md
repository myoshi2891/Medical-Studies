# 頭頸部の統合3Dアトラス

`/anatomy` の全体像に、神経・血管・脳・脳幹・頭蓋骨・頸椎・筋の7系統を重ねて表示する。
各系統のボタンまたは3Dラベルから詳細モーダルを開き、42部位から選択できる。
選択後も系統全体を表示し、該当部位だけを強調色へ切り替える。
部位の位置・機能、臨床上の補足と表示限界、参考資料を日本語・英語で併記する。

## 操作

- チェックボックスで各系統の表示を切り替える。初期状態は全系統を表示。
- 全体像・全系統の欄・詳細画面の「3Dラベルを表示」でピンの表示を切り替える。
  ラベルを隠しても部位一覧と解説を利用できる。系統別の欄では従来の自動回転も維持する。
- 脳・脳幹欄は「脳／脳幹」、骨・頚椎欄は「頭蓋骨／頸椎」のボタンで系統を切り替える。
  初期表示は脳・頭蓋骨。切替後もラベル表示と自動回転の設定を保つ。
- 骨・脳・筋の透過表示を切り替え、内側の構造を確認する。
- ドラッグで回転、ホイール・ピンチで拡大、視点ボタンで方向を戻す。
- 日英の部分一致で部位を検索する。詳細画面でも同じ系統内を検索できる。
- 詳細画面の部位一覧は内部スクロールを設けず、同じ系統の全項目を一度に表示する。
- 部位を選択すると、左の系統全体モデルで該当部位だけを強調し、右の観察欄を日英解説へ切り替える。
- モーダルはEscape・閉じるボタン・背景クリックで閉じ、元の操作位置へフォーカスを戻す。
  ネイティブdialogを使い、背景の操作を無効化する。
- WebGLやモデル読込が失敗しても、部位一覧と日英の解説を保持し、再読込を提供する。

## データと再生成

神経・血管・脳／脳幹・骨／頚椎・筋の全欄が、全体像と同じモデル・操作を使う
`AtlasSectionViewer` へ移行済み。`AtlasSectionGroup` が複数系統の切替を担当する。
今後の追加・変更は [系統別3Dの移行手順](anatomy-section-migration.md) を参照する。

既存のBodyParts3D v4.0の `is_a` OBJを使用し、202個の元メッシュを42部位へ統合する。
`web-next/lib/anatomy/atlas.ts` の部位定義と元の英語名の正規表現を照合する。
同じOBJ IDの重複使用と空の選択は生成時のエラーとする。

```bash
cd web-next
bun scripts/build-head-neck-atlas.mjs
```

出力は `public/models/atlas/` の50ファイル（全体1、系統7、部位42）と
`lib/anatomy/atlas-models.json`。全体GLBは約2 MB、全GLBは約6 MB。
ビルドにはローカルの元OBJが必要だが、Webアプリの実行には生成済みGLBのみ必要。

個別モデルを別々の原点へ移動せず、全ファイルに同一の単位・回転・平行移動を適用する。
詳細表示では系統全体のGLBを維持し、名前付きマテリアルを使って選択部位の色だけを変更する。
既存のmodel-viewerの公開APIで強調色・透過・表示を制御する。
新規ライブラリやCSPの許可ホスト追加は不要。Dracoデコーダも既存の自己ホスト配信を使う。

## 収録範囲

全ての系統が見えることと、全ての解剖構造を網羅することは異なる。
大後頭神経、三叉神経本幹、頸神経根、椎間板・靱帯、脳幹内の神経核は未収録。
大脳は元データに含まれる脳回と白質で構成し、全脳回を個別には分離しない。
一部の構造は左右・関連枝を同じ部位としてグループ化する。
筋の付着と全体形状を保つため、僧帽筋などは上背部まで表示する。
TCCは尾側の三叉神経脊髄路核から上位頸髄へ続く機能的な領域で、延髄そのものではない。

## 検証

GLBの実在・部位マテリアル・共通座標・元OBJの重複排除、日英データ、レイヤー切替、
部位検索・選択部位の強調と色の復元、読込失敗と再試行、モーダルの開閉とフォーカス復帰を契約テストで検証する。
実際のWebGL描画はブラウザで別途確認する。

検証済み: 7系統・42部位の日英解説、実マテリアルの表示切替、選択部位の強調と色の復元、
一覧の全件表示、Escapeでの閉鎖とフォーカス復帰。
全系統の移行後は全887テスト、型チェック、変更ファイルのLintが通過した。
脳／脳幹・頭蓋骨／頸椎の切替、設定保持、各系統の部位一覧・詳細導線も自動検証済み。
全体Lintには今回の変更対象外の `app/icon.svg` に代替テキスト不足のエラーが残る。
実際のWebGL描画、PC幅と390px幅の表示は別途確認する。本番ビルドはユーザー側で実施する。
Node.js 22の実験的Web Storageがjsdomと競合する環境では、
`NODE_OPTIONS=--no-experimental-webstorage bun run test` でjsdom側のStorageを使用する。
